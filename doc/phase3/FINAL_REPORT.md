# Финальный отчёт по Phase 3

## Цель

Phase 3 была посвящена исследованию **политик принятия решений** на основе накопленной evidence. Мы хотели понять, какая стратегия использования информации (поддержка, чистые данные, баланс, согласованность) даёт наилучшие результаты в задачах с неопределённостью и конфликтами.

## Методология

- Использовалась единая модель накопления evidence (support/conflict).
- Четыре политики: PERSISTENT, NET, CONSISTENCY, SUPPORT.
- Тесты охватывали: ручные сценарии, статистические бенчмарки, активное обучение, симуляцию программиста.
- Метрики: accuracy, coverage, avg_queries, success_rate.

## Результаты

### Сравнение политик (test05–test06)

| Политика | Accuracy | Coverage | Характер |
|----------|----------|----------|----------|
| **SUPPORT** | 0.9–1.0 | 0.85–1.0 | Решительная, игнорирует конфликт |
| **NET** | 0.8–0.99 | 0.75–0.95 | Балансирует поддержку и конфликт |
| **CONSISTENCY** | 0.2–0.8 | 0.6–0.9 | Чувствительна к качеству evidence |
| **PERSISTENT** | 0.01–0.2 | 0.7–0.9 | Очень консервативная |

### Активное обучение (test07–test08)

- **SUPPORT** с порогом 0.5–0.6 даёт accuracy ≈ 0.98 и avg_queries ≈ 1.5.
- **NET** с порогом 0.3–0.5 даёт accuracy ≈ 0.95 и avg_queries ≈ 0.5.
- **PERSISTENT** и **CONSISTENCY** неэффективны при высоких порогах.

### Симуляция программиста (test09)

- **SUPPORT**: success_rate = 0.895 (без противоречий), 0.805 (с 2 противоречиями), avg_queries ≤ 0.7.
- **NET**: success_rate = 0.880 (без), 0.775 (с 2), avg_queries ≤ 0.72.
- **PERSISTENT**: success_rate ≈ 0.45–0.48, avg_queries ≈ 5 (почти всегда исчерпывает бюджет).
- **Вывод**: SUPPORT — лучшая политика для задач с уточнениями.

## Заключение

Phase 3 показала, что **выбор политики принятия решений критически важен**. Наилучшие результаты даёт политика **SUPPORT**, которая использует только количество поддержки, игнорируя конфликт. Это контринтуитивно, но объяснимо: в условиях, где можно получить дополнительные уточнения, конфликт не должен препятствовать выбору кандидата с сильной поддержкой.

Таким образом, **идеальный ИИ-программист** должен действовать по принципу «максимальной поддержки», делая минимальное число уточнений и доверяя количеству подтверждений.
