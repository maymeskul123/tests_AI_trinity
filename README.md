# Эксперимент: Binary vs Ternary vs Quaternary Agents

## 1. Цель эксперимента

Целью данного эксперимента было сравнить различные системы принятия решений:

* **BINARY** — бинарная логика;
* **TERNARY** — троичная логика;
* **QUATERNARY** — четверичная логика.

Основной вопрос исследования:

> Может ли увеличение количества логических состояний улучшить качество принятия решений агентом в условиях неопределённости, конфликтующей информации и ограниченного бюджета запросов?

Эксперимент специально построен так, чтобы проверить не только ситуацию с «идеальными данными», но и более реалистичные условия:

* наличие неизвестной информации;
* наличие конфликтующей информации;
* ограничение количества запросов;
* возможность отказаться от решения (`ABSTAIN`);
* наличие ложной уверенности (`FALSE_CONFIDENCE`).

---

# 2. Общая идея теста

Агент получает некоторую информацию и должен принять решение.

При этом среда может содержать различные уровни:

1. **неопределённости**;
2. **конфликтов между источниками информации**;
3. **ограничений на количество запросов**.

Каждый агент работает с одинаковой задачей, но использует различную модель внутренних состояний.

Сравнение позволяет определить:

* влияет ли количество логических состояний на качество решений;
* помогает ли более сложная логика лучше работать с конфликтами;
* снижает ли многозначная логика количество ошибок;
* появляется ли преимущество только при определённых условиях.4

---

# 3. Типы агентов

## BINARY

Бинарный агент работает с двумя основными состояниями:

```text
TRUE / FALSE
```

или концептуально:

```text
ДА / НЕТ
```

Это наиболее простая модель принятия решений.

Преимущества:

* простота;
* минимальная сложность;
* быстрое принятие решения.

Недостаток заключается в том, что неопределённость и конфликтующая информация должны быть каким-либо образом сведены к одному из двух состояний.

---

## TERNARY

Троичный агент использует три состояния.

Концептуально это может быть представлено как:

```text
TRUE
FALSE
UNKNOWN
```

То есть система получает отдельное состояние:

```text
UNKNOWN = неизвестно / недостаточно информации
```

Это потенциально позволяет агенту не смешивать отсутствие информации с отрицательным ответом.

---

## QUATERNARY

Четверичный агент использует четыре состояния.

Концептуально возможная интерпретация:

```text
TRUE
FALSE
UNKNOWN
CONFLICT
```

или:

```text
1. Подтверждено
2. Опровергнуто
3. Неизвестно
4. Конфликтующая информация
```

Главное отличие четверичной модели состоит в разделении двух разных ситуаций:

```text
UNKNOWN
```

и

```text
CONFLICT
```

Это принципиально разные состояния.

### UNKNOWN

Информации недостаточно.

Например:

```text
Источник A: нет данных
Источник B: нет данных
```

### CONFLICT

Информация есть, но источники противоречат друг другу.

Например:

```text
Источник A: TRUE
Источник B: FALSE
```

Бинарная система может быть вынуждена выбрать один ответ.

Четверичная система может сохранить сам факт конфликта как отдельное состояние.

# 4. Параметры эксперимента

В каждом тесте изменялись следующие параметры.

---

## `unknown_rate`

Доля неизвестной или отсутствующей информации.

Например:

```text
unknown_rate = 0.0
```

означает отсутствие неизвестных данных.

```text
unknown_rate = 0.2
```

означает, что примерно 20% информации являются неизвестными или недостаточными.

В тестах использовались значения:

```text
0.0
0.2
0.4
```

---

## `conflict_rate`

Доля конфликтующей информации.

Например:

```text
conflict_rate = 0.0
```

означает отсутствие конфликтов.

```text
conflict_rate = 0.1
```

означает примерно 10% конфликтующих данных.

```text
conflict_rate = 0.2
```

означает примерно 20% конфликтов.

Использовались значения:

```text
0.0
0.1
0.2
```

---

## `budget`

Количество доступных запросов или ресурсов, которые агент может использовать для получения информации.

Использовались бюджеты:

```text
1
2
3
4
5
6
8
10
12
```

Чем больше бюджет, тем больше информации агент потенциально может получить.

---

## `agent`

Тип логической системы:

```text
BINARY
TERNARY
QUATERNARY
```

---

# 5. Метрики результатов

В результатах использовались следующие показатели.

---

## `correct`

Доля полностью правильных решений.

Например:

```text
correct = 1.0
```

означает 100% правильных решений.

```text
correct = 0.92
```

означает 92% правильных решений.

---

## `queries`

Среднее количество реально использованных запросов.

Это важно, поскольку агент может иметь максимальный бюджет, но не обязательно использовать его полностью.

Например:

```text
budget = 10
queries = 7.27
```

означает, что агент имел возможность сделать до 10 запросов, но в среднем использовал около 7.27.

---

## `information`

Количество или объём полученной полезной информации.

Этот показатель показывает, насколько эффективно дополнительные запросы превращаются в новую информацию.

Чем выше значение, тем больше информационного ресурса было получено в процессе решения задачи.

---

## `false_confidence`

Доля случаев ложной уверенности.

Это одна из наиболее важных метрик.

Она показывает ситуацию:

> агент уверен в своём ответе, но этот ответ неправильный.

Например:

```text
false_confidence = 0.05
```

означает примерно 5% случаев ложной уверенности.

Высокая ложная уверенность является особенно опасной, поскольку система:

* не просто ошибается;
* ошибается уверенно.

---

## `abstain`

Доля случаев, когда агент отказался принимать решение.

Например:

```text
abstain = 0.02
```

означает, что примерно в 2% случаев агент решил:

> недостаточно оснований для уверенного ответа.

Отказ от решения не обязательно является плохим результатом.

В системах с неопределённостью иногда лучше сказать:

```text
НЕ ЗНАЮ
```

чем уверенно дать неправильный ответ.

---

## `reward`

Итоговая функция награды.

Она объединяет:

* правильность решений;
* стоимость запросов;
* штрафы за ошибки;
* возможные штрафы за отказ от решения.

Поэтому:

```text
reward
```

является итоговой метрикой эффективности стратегии.

Чем выше значение, тем лучше общая стратегия.

---

# 6. Базовый сценарий: нет неопределённости и конфликтов

Параметры:

```text
unknown_rate = 0.0
conflict_rate = 0.0
```

Во всех протестированных бюджетах результаты для трёх агентов оказались практически одинаковыми:

```text
BINARY
TERNARY
QUATERNARY
```

Например, при:

```text
budget = 1
```

все агенты показали:

```text
correct = 0
abstain = 1.0
```

То есть при недостаточном бюджете агент не мог получить достаточно информации и полностью воздерживался от решения.

При увеличении бюджета:

```text
budget = 2
budget = 3
...
budget = 12
```

количество используемых запросов и информации росло практически одинаково для всех типов агентов.

### Вывод

В простой среде, где:

* нет неизвестных данных;
* нет конфликтующей информации;

многозначная логика **не даёт автоматического преимущества**.

Это важный результат.

Само увеличение количества состояний:

```text
2 → 3 → 4
```

не улучшает систему, если задача не требует различать дополнительные состояния.

---

# 7. Сценарий с конфликтами

Параметры:

```text
unknown_rate = 0.0
conflict_rate = 0.1
```

При небольших бюджетах различия между агентами практически отсутствуют.

Однако при увеличении бюджета начинает появляться интересная разница.

Например:

```text
budget = 8
```

BINARY:

```text
queries ≈ 6.329
information ≈ 16.12
```

QUATERNARY:

```text
queries = 8
information ≈ 20.21
```

При:

```text
budget = 10
```

BINARY:

```text
queries ≈ 7.27
information ≈ 18.54
```

QUATERNARY:

```text
queries = 10
information ≈ 25.23
```

При:

```text
budget = 12
```

BINARY:

```text
queries ≈ 8.16
information ≈ 20.81
```

QUATERNARY:

```text
queries = 12
information ≈ 30.25
```

### Наблюдение

В условиях конфликтующей информации четверичная система продолжает использовать дополнительные ресурсы.

Бинарная и троичная системы начинают использовать бюджет менее полно.

Это может означать, что дополнительное состояние:

```text
CONFLICT
```

позволяет четверичному агенту продолжать обработку информации вместо преждевременного схлопывания состояния в:

```text
TRUE
```

или:

```text
FALSE
```

---

# 8. Сценарий с высокой неопределённостью

Параметры:

```text
unknown_rate = 0.4
conflict_rate = 0.0
```

В этом сценарии количество полезной информации резко уменьшается.

Например:

```text
budget = 1
information ≈ 0.063
```

При:

```text
budget = 12
```

получаем:

```text
information ≈ 3.07
```

При этом все три системы показывают практически одинаковые результаты.

### Вывод

Если проблема состоит только в отсутствии информации, а не в необходимости различать различные типы неопределённости, то:

```text
BINARY ≈ TERNARY ≈ QUATERNARY
```

То есть дополнительное количество логических состояний само по себе не компенсирует отсутствие данных.

---

# 9. Критический сценарий: высокая неопределённость + конфликты

Наиболее интересные результаты появляются при:

```text
unknown_rate = 0.4
conflict_rate = 0.1
```

и особенно:

```text
unknown_rate = 0.4
conflict_rate = 0.2
```

Здесь одновременно присутствуют:

```text
UNKNOWN
+
CONFLICT
```

Именно в такой среде четверичная модель начинает принципиально отличаться от остальных.

---

# 10. Результаты при `unknown_rate = 0.4` и `conflict_rate = 0.1`

При небольшом бюджете различия минимальны.

Однако с ростом бюджета появляются различия в:

* количестве запросов;
* количестве информации;
* отказах;
* итоговой награде.

Например:

```text
budget = 8
```

### BINARY

```text
correct ≈ 0.001
queries ≈ 7.58
information ≈ 0.379
false_confidence ≈ 0.0008
abstain ≈ 0.9982
```

### TERNARY

```text
correct ≈ 0.0016
queries ≈ 7.65
information ≈ 0.427
false_confidence = 0
abstain ≈ 0.9984
```

### QUATERNARY

```text
correct = 0
queries = 8
information ≈ 0.170
false_confidence = 0
abstain = 1.0
```

### Интерпретация

Четверичный агент в данном сценарии ведёт себя наиболее консервативно.

Он практически всегда выбирает:

```text
ABSTAIN
```

Это означает:

> система не пытается искусственно принять решение, когда различает слишком много проблемных состояний.

С одной стороны, это снижает риск ложных решений.

С другой стороны, текущая функция награды штрафует постоянный отказ.

# 12. Главное наблюдение эксперимента

Получился очень важный результат.

В сложной среде:

```text
UNKNOWN + CONFLICT
```

четверичный агент не начинает давать больше правильных ответов.

Вместо этого он начинает:

```text
ОТКАЗЫВАТЬСЯ ОТ НЕОБОСНОВАННЫХ РЕШЕНИЙ
```

То есть его преимущество проявляется не как:

```text
"я знаю больше"
```

а как:

```text
"я лучше понимаю, когда информации недостаточно для решения"
```

Это фундаментально другое преимущество.

---

# 13. Ложная уверенность

Один из самых интересных результатов связан с:

```text
false_confidence
```

В сложных сценариях бинарные и троичные агенты начинают:

* иногда принимать решения;
* иногда ошибаться;
* иногда ошибаться уверенно.

Например:

```text
unknown = 0.4
conflict = 0.2
budget = 12
```

получаем:

```text
BINARY false_confidence ≈ 0.0548
TERNARY false_confidence ≈ 0.0568
QUATERNARY false_confidence = 0
```

Четверичный агент вообще не демонстрирует ложной уверенности.

Причина:

он сохраняет отдельные состояния:

```text
UNKNOWN
```

и

```text
CONFLICT
```

вместо того чтобы преобразовывать их в искусственное:

```text
TRUE / FALSE
```

---

# 14. Почему QUATERNARY часто имеет `correct = 0`

На первый взгляд это может выглядеть как плохой результат:

```text
correct = 0
```

Но его нельзя интерпретировать отдельно от:

```text
abstain = 1.0
```

Четверичный агент фактически говорит:

> Я не могу принять обоснованное решение в этой среде.

Это отличается от ситуации:

```text
дать случайный ответ
```

или:

```text
дать неправильный ответ с высокой уверенностью.
```

Поэтому в текущем эксперименте необходимо различать два понятия:

### Accuracy

Сколько правильных ответов дал агент.

### Epistemic Safety

Насколько хорошо агент понимает границы собственных знаний.

По второй характеристике четверичная модель показывает потенциально интересный результат.

---

# 15. Основная проблема текущей reward-функции

Текущая функция награды, судя по результатам, значительно штрафует:

```text
ABSTAIN
```

Поэтому консервативная стратегия четверичного агента получает отрицательную награду.

Например:

```text
QUATERNARY
abstain = 1.0
false_confidence = 0
```

но:

```text
reward < 0
```

Это означает, что текущая reward-функция оценивает отказ как достаточно дорогую стратегию.

Однако для реальных систем это зависит от задачи.

---

## Пример

Для игры:

```text
ABSTAIN
```

может быть плохим действием.

Но для:

* медицинской диагностики;
* автономного транспорта;
* финансовых решений;
* систем безопасности;
* научного анализа;
* юридических систем;
* ИИ-агентов;

ответ:

```text
"недостаточно информации"
```

может быть намного лучше, чем уверенная ошибка.

# 17. Главный научный вывод

Эксперимент показывает следующее:

> Увеличение количества логических состояний не даёт автоматического преимущества.

Если задача простая:

```text
TRUE / FALSE
```

то бинарная логика может работать не хуже.

Однако преимущество многозначной логики появляется тогда, когда сама среда содержит несколько качественно различных типов неопределённости.

Например:

```text
FALSE
≠
UNKNOWN
≠
CONFLICT
```

Если эти состояния действительно различны, их объединение в одну категорию приводит к потере информации.

# 18. Главный вывод для архитектуры ИИ

Полученные результаты поддерживают следующую гипотезу:

> Дополнительные логические состояния полезны не потому, что они «умнее» сами по себе, а потому, что позволяют сохранять структуру неопределённости.

Бинарная система может представить:

```text
TRUE / FALSE
```

Троичная:

```text
TRUE / FALSE / UNKNOWN
```

Четверичная:

```text
TRUE / FALSE / UNKNOWN / CONFLICT
```

Каждый дополнительный уровень может сохранять новый тип информации.

Таким образом, потенциальное преимущество заключается не в арифметическом увеличении количества состояний:

```text
2 → 3 → 4
```

а в увеличении **различимости типов эпистемического состояния системы**.

---

# 19. Предварительная гипотеза

На основании эксперимента можно сформулировать следующую гипотезу:

> Чем сложнее среда и чем больше различных типов неопределённости она содержит, тем выше потенциальная ценность многозначной логики.

Однако это преимущество должно проявляться только при правильной архитектуре.

Простое добавление новых состояний недостаточно.

Необходимо, чтобы:

1. агент умел использовать эти состояния;
2. политика принятия решений учитывала различия между ними;
3. reward-функция не штрафовала рациональную осторожность;
4. существовал механизм преобразования состояний в дальнейшие действия.

# 20. Следующий этап исследования

Текущие результаты показывают необходимость следующего этапа.

Необходимо проверить модель, где QUATERNARY не просто делает:

```text
ABSTAIN
```

при обнаружении:

```text
UNKNOWN
или
CONFLICT
```

а использует эти состояния как сигнал для выбора следующего действия.

Например:

```text
UNKNOWN
    ↓
искать дополнительную информацию
```

```text
CONFLICT
    ↓
искать независимый источник
```

```text
TRUE
    ↓
принимать решение
```

```text
FALSE
    ↓
принимать противоположное решение
```

Таким образом, четверичная логика должна использоваться не как:

```text
4 варианта ответа
```

а как:

```text
4 различных состояния управления процессом поиска информации.
```

# 21. Предлагаемая архитектура следующего теста

```text
                ┌──────────────┐
                │   QUESTION   │
                └──────┬───────┘
                       │
                       ▼
                ┌──────────────┐
                │ INFORMATION  │
                └──────┬───────┘
                       │
                       ▼
          ┌─────────────────────────┐
          │  QUATERNARY CLASSIFIER  │
          └─────┬──────┬──────┬─────┘
                │      │      │
             TRUE    FALSE  UNKNOWN  CONFLICT
                │      │      │        │
                ▼      ▼      ▼        ▼
             ANSWER  ANSWER  SEARCH   VERIFY
                              MORE      MORE
```

В этой архитектуре:

```text
UNKNOWN
```

не означает конец процесса.

Это означает:

```text
SEARCH MORE
```

А:

```text
CONFLICT
```

означает:

```text
VERIFY / FIND INDEPENDENT EVIDENCE
```

# 22. Итоговый вывод

На текущем этапе эксперимент показывает:

### 1.

В простых задачах:

```text
BINARY ≈ TERNARY ≈ QUATERNARY
```

Дополнительная логика не даёт автоматического выигрыша.

### 2.

При появлении конфликтующей информации многозначные системы начинают вести себя иначе.

### 3.

При высокой неопределённости и конфликтах QUATERNARY демонстрирует максимальную осторожность.

### 4.

QUATERNARY практически исключает:

```text
FALSE CONFIDENCE
```

в протестированных сценариях.

### 5.

Главное потенциальное преимущество четверичной системы — не увеличение accuracy само по себе.

Главное преимущество:

```text
лучшее разделение состояний знания
```

между:

```text
Я знаю, что это TRUE
Я знаю, что это FALSE
Я не знаю
У меня есть противоречивые данные
```

### 6.

Следующий этап эксперимента должен проверить активную стратегию:

```text
UNKNOWN → искать информацию
CONFLICT → проверять конфликт
TRUE/FALSE → принимать решение
```

Именно такой тест позволит проверить, может ли четверичная логика дать не только более безопасное, но и **реальное преимущество в качестве принятия решений**.

# 23. Краткое резюме

```text
Бинарная логика:
быстрая и эффективная в простых задачах.

Троичная логика:
добавляет понятие неизвестности.

Четверичная логика:
разделяет неизвестность и конфликт.

Главный результат:
дополнительные состояния становятся полезными только тогда,
когда система использует их для разных стратегий поведения.
```

**Итоговая гипотеза проекта:**

> Будущее преимущество многозначной логики в ИИ может заключаться не в замене бинарных вычислений, а в создании более богатого слоя представления знаний, неопределённости, конфликтов и стратегий дальнейшего поиска информации.
